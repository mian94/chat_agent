### 🎯 **模块1：Vue3 Composition API**

#### 📚 知识点讲解
**位置**：`frontend/src/views/Home.vue` 第152-200行，`frontend/src/stores/chat.ts` 第1-240行

**语法点**：
1. **`<script setup>`语法糖**：
   ```vue
   <script setup lang="ts">
   // 代码直接写在这里，无需export default
   const count = ref(0)
   </script>
   ```
   - **作用**：简化组件逻辑，自动暴露变量给模板
   - **优势**：比Options API（data、methods分开写）更简洁
   - **原理**：编译时自动处理，性能更好

2. **`ref`和`reactive`**：
   ```typescript
   import { ref, reactive } from 'vue'
   
   // ref：基本类型响应式
   const count = ref(0)  // count.value = 1
   
   // reactive：对象响应式
   const state = reactive({ name: '张三', age: 20 })
   ```

3. **`computed`计算属性**：
   ```typescript
   const doubleCount = computed(() => count.value * 2)
   ```

4. **自定义图标组件**（`Home.vue`第158-179行）：
   ```typescript
   const CodeIcon = {
     setup(props) {
       return () => h('svg', { /* SVG属性 */ })
     }
   }
   ```
   - **为什么用`h`函数**：Vue3+TS不支持JSX，用`h`函数手动创建虚拟DOM

#### 🎯 面试题
**问题1**：Vue3的Composition API相比Options API有什么优势？
**答案**：Composition API有三大优势：第一，逻辑复用更灵活，可以通过自定义Hook封装可复用逻辑，避免mixins的命名冲突；第二，代码组织更清晰，相关逻辑可以集中在一起，而不是分散在data、methods等选项中；第三，TypeScript支持更好，类型推断更准确，开发体验更好。

**问题2**：ref和reactive有什么区别？分别在什么场景使用？
**答案**：ref用于基本类型（string、number、boolean）的响应式，通过.value访问；reactive用于对象类型（Object、Array）的响应式，直接访问属性。使用场景：单个值用ref，复杂对象用reactive。注意：ref也可以包装对象，但深层响应性需要.value访问。

**问题3**：Vue3中为什么不支持JSX？如何解决？
**答案**：Vue3+TypeScript默认不支持JSX语法，因为Vue的模板编译器和JSX的编译器不同。解决方案有两种：一是使用h函数手动创建虚拟DOM，如自定义图标组件；二是配置@vue/babel-plugin-jsx插件支持JSX。项目中采用h函数方式，更轻量且类型安全。

### 🎯 **模块2：TypeScript类型系统**

#### 📚 知识点讲解
**位置**：`frontend/src/types/index.ts`，`backend/src/types/index.ts`

**语法点**：
1. **`interface`接口**：
   ```typescript
   interface ChatMessage {
     id: string
     role: MessageRole
     content: string
     timestamp: number
   }
   ```

2. **`type`类型别名**：
   ```typescript
   type MessageRole = 'user' | 'assistant' | 'system' | 'tool'
   type TutorMode = 'quiz' | 'qa' | 'mock'
   ```

3. **泛型**：
   ```typescript
   interface ApiResponse<T = unknown> {
     success: boolean
     data?: T
     error?: string
   }
   ```

4. **类型导入导出**：
   ```typescript
   import type { ChatMessage } from '@/types'  // 只导入类型
   export type { ChatSession }  // 只导出类型
   ```

#### 🎯 面试题
**问题1**：TypeScript相比JavaScript有什么优势？
**答案**：TypeScript有四大优势：第一，静态类型检查，在编译时发现错误，减少运行时bug；第二，更好的代码提示和自动补全，提高开发效率；第三，接口和类型定义，让代码更易维护；第四，支持最新ECMAScript特性，编译后兼容旧浏览器。

**问题2**：interface和type有什么区别？
**答案**：interface和type都能定义对象类型，但有区别：interface可以重复声明自动合并，type不行；type可以定义联合类型、交叉类型、基本类型别名，interface不行；interface支持extends继承，type支持&交叉。项目中，定义对象结构用interface，定义联合类型用type。

**问题3**：什么是泛型？举例说明使用场景。
**答案**：泛型是类型参数化，让函数或接口支持多种类型。例如ApiResponse<T>，T可以是HealthCheckResponse、ChatMessage等不同数据类型。使用场景：API响应包装、通用工具函数、集合类型等。好处是类型安全且复用性强。

### 🎯 **模块3：Pinia状态管理**

#### 📚 知识点讲解
**位置**：`frontend/src/stores/chat.ts` 第143-239行

**语法点**：
1. **`defineStore`定义Store**：
   ```typescript
   export const useChatStore = defineStore('chat', () => {
     // 状态
     const sessions = ref<ChatSession[]>([])
     
     // 计算属性
     const activeSession = computed(() => { ... })
     
     // 方法
     function createSession() { ... }
     
     return { sessions, activeSession, createSession }
   })
   ```

2. **Composition API风格**：
   - 使用`ref`、`computed`定义状态
   - 普通函数定义方法
   - 必须return暴露给组件

3. **Mock数据**（第20-141行）：
   - `createMockSessions()`生成测试数据
   - 包含三种辅导模式示例
   - 便于开发和演示

#### 🎯 面试题
**问题1**：Pinia和Vuex有什么区别？为什么选择Pinia？
**答案**：Pinia是Vue3官方推荐的状态管理库，相比Vuex有三大优势：第一，API更简洁，没有mutations，只有state、getters、actions；第二，完美支持TypeScript，类型推断准确；第三，支持Composition API风格，代码组织更灵活。Pinia体积也更小，性能更好。

**问题2**：Pinia中如何定义和使用Store？
**答案**：使用defineStore定义Store，第一个参数是唯一ID，第二个参数是setup函数。在setup函数中用ref定义状态，computed定义计算属性，普通函数定义方法。最后return暴露。组件中通过useChatStore()获取实例，直接访问状态和方法。

**问题3**：为什么要在Store中使用Mock数据？
**答案**：Mock数据用于开发阶段模拟后端接口数据，好处有三个：第一，前后端并行开发，不依赖后端接口；第二，便于UI开发和测试；第三，演示项目功能。项目中createMockSessions()生成三种辅导模式的示例数据，展示完整功能。

#### 🎯 面试题
**问题1**：Vue Router的导航守卫有哪些？分别在什么场景使用？
**答案**：Vue Router有三种导航守卫：全局守卫（beforeEach、afterEach）、路由独享守卫（beforeEnter）、组件内守卫（beforeRouteEnter等）。使用场景：全局守卫用于登录验证、权限控制；路由独享守卫用于特定路由的权限；组件内守卫用于页面离开前提醒保存。

**答案**：使用动态import实现路由懒加载：`component: () => import('./views/Home.vue')`。好处是首屏加载更快，按需加载路由组件。Webpack会自动分割代码，生成单独的chunk文件。

### 🎯 **模块5：Axios请求封装**

#### 📚 知识点讲解
**位置**：`frontend/src/api/request.ts`，`frontend/src/api/index.ts`

**语法点**：
1. **创建axios实例**：
   ```typescript
   const request = axios.create({
     baseURL: '/api',
     timeout: 30000
   })
   ```

2. **请求拦截器**：
   ```typescript
   request.interceptors.request.use(config => {
     // 添加token、修改请求头
     return config
   })
   ```

3. **响应拦截器**：
   ```typescript
   request.interceptors.response.use(response => {
     // 统一处理响应数据
     if (response.data.success) {
       return response
     }
     return Promise.reject(new Error('请求失败'))
   })
   ```

#### 🎯 面试题
**问题1**：Axios拦截器的作用是什么？如何使用？
**答案**：Axios拦截器用于统一处理请求和响应。请求拦截器可以在发送请求前添加token、修改请求头；响应拦截器可以统一处理错误、转换数据格式。使用request.interceptors.request.use()和response.use()添加。项目中用于统一错误处理和类型转换。

**问题2**：如何封装一个通用的API请求模块？
**答案**：封装步骤：1）创建axios实例配置baseURL和超时；2）添加请求拦截器处理token；3）添加响应拦截器处理错误和数据转换；4）定义具体API函数如checkHealth()；5）导出request实例供其他模块使用。好处是统一管理请求逻辑，减少重复代码。

### 🎯 **模块6：Express后端**

#### 📚 知识点讲解
**位置**：`backend/src/index.ts`，`backend/src/routes/index.ts`

**语法点**：
1. **Express应用创建**：
   ```typescript
   const app = express()
   app.use(cors())  // 跨域中间件

   ```

2. **路由定义**：
   ```typescript

     res.json({ success: true })
   })
   ```

3. **中间件执行顺序**：
   - 按app.use()顺序执行
   - 路由中间件匹配路径执行
   - 错误处理中间件最后执行

#### 🎯 面试题
**问题1**：Express中间件的执行顺序是什么？
**答案**：Express中间件按app.use()顺序执行，从上到下。每个中间件通过next()传递给下一个。路由中间件匹配路径执行。错误处理中间件（4个参数）最后执行。理解执行顺序对调试和功能实现很重要。

**问题2**：如何实现一个RESTful API？
**答案**：RESTful API设计原则：1）使用名词表示资源（/api/chat）；2）HTTP方法表示操作（GET获取、POST创建、PUT更新、DELETE删除）；3）状态码表示结果（200成功、404未找到）；4）JSON格式传输数据。项目中/api/health是健康检查接口，/api/chat是聊天接口。

#### **模块1：SSE流式通信（Server-Sent Events）**

**位置**：`backend/src/chat-handler.ts`，`frontend/src/api/index.ts`

**React类比**：
```javascript
// React中类似fetch + ReadableStream
const response = await fetch('/api/chat', { method: 'POST', body: JSON.stringify(data) })
const reader = response.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  // 处理流式数据
}
```

**知识点**：
1. **SSE vs WebSocket**：
   - SSE：单向通信（服务器→客户端），基于HTTP，自动重连
   - WebSocket：双向通信，需要单独协议升级
   - 项目选择SSE：因为聊天只需要服务器推送，SSE更简单

2. **SSE响应格式**：
   ```
   data: {"type":"delta","content":"你"}
   data: {"type":"delta","content":"好"}
   data: {"type":"done"}
   ```

3. **流式处理挑战**：
   - 多字节字符截断（中文、emoji）
   - 缓冲区处理
   - 错误处理和重试

**面试题**：
**问题1**：SSE和WebSocket有什么区别？分别在什么场景使用？
**答案**：SSE是单向通信，基于HTTP，适合服务器推送场景如实时通知、聊天流式响应；WebSocket是双向通信，需要协议升级，适合实时交互如在线游戏、协同编辑。SSE实现简单，自动重连；WebSocket功能更强大但复杂度更高。

**问题2**：如何处理SSE中的多字节字符截断问题？
**答案**：使用TextDecoder的stream模式解码，设置`{ stream: true }`确保多字节字符不被截断。在缓冲区处理时，保留不完整的行等待下一个chunk。项目中使用`decoder.decode(value, { stream: true })`和行缓冲区解决。

## 📝 **常见问题解答**

### **Q1：Vue3和React的主要区别是什么？**
**A**：Vue3使用模板语法，React使用JSX；Vue3的响应式系统基于Proxy，React基于状态提升；Vue3官方推荐Pinia状态管理，React常用Redux或Context。

### **Q2：TypeScript在项目中的作用是什么？**
**A**：TypeScript提供静态类型检查，减少运行时错误；提供更好的代码提示和自动补全；支持接口定义，提高代码可维护性。

### **Q3：为什么选择SSE而不是WebSocket？**
**A**：聊天功能只需要服务器推送，SSE基于HTTP实现简单，自动重连；WebSocket适合双向实时交互，实现复杂度更高。

### **Q4：IndexedDB的使用场景是什么？**
**A**：适合存储结构化数据，如聊天记录、用户数据；容量大（几百MB），支持索引查询；异步API，不会阻塞主线程。
