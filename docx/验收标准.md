# 前端八股面试智能辅导 Agent — 验收标准

> 版本：v1.0  
> 对应 PRD 版本：v1.0  
> 说明：以下验收标准按照阶段和模块划分，每个验收项需满足「通过/不通过」的二元判定。

---

## 1. 基础架构验收

### 1.1 项目工程

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| A-01 | 前端项目初始化 | Vue3 + Vite + TypeScript 项目可正常 `npm run dev` 启动，无报错 | 必须 |
| A-02 | 后端项目初始化 | Express + TypeScript 项目可正常 `npm run dev` 启动，监听指定端口 | 必须 |
| A-03 | 前后端通信 | 前端可成功调用后端 `/api/health` 接口，返回 `{ status: 'ok' }` | 必须 |
| A-04 | ESLint 配置 | 全项目运行 `npm run lint` 无 error（warn 不超过 5 个） | 必须 |
| A-05 | TypeScript 编译 | 前后端 `tsc` 编译无 error，严格模式开启 | 必须 |
| A-06 | 目录结构合理 | 前后端分离，按功能模块拆分目录，不出现单文件超过 300 行 | 建议 |

### 1.2 环境配置

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| A-07 | 环境变量管理 | API Key、端口等配置通过 `.env` 管理，`.env.example` 提交至仓库 | 必须 |
| A-08 | 启动文档 | README 中写明前后端分别的启动步骤，新环境下按步骤可 5 分钟内运行 | 必须 |
| A-09 | 依赖管理 | `package.json` 中无未使用的依赖，无高危漏洞依赖 | 建议 |

## 3. Agent 核心能力验收

### 3.1 基础对话

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| AG-01 | 基本问答 | 发送任意思问，Agent 能在合理时间内返回有意义的回答 | 必须 |
| AG-02 | 上下文理解 | 多轮对话中 Agent 能引用前文信息（如上一轮提到的知识点） | 必须 |
| AG-03 | 篇幅控制 | Agent 回答不冗长，对于简单问题不输出大段无关内容 | 建议 |
| AG-04 | 回答准确性校验 | 高频八股问题（如"Vue 生命周期"）的回答与标准参考集包含的关键要点一致，无重大偏差 | 建议 |

### 3.2 工具调用

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| AG-04 | 联网搜索触发 | 提问"最近 React 新版本有什么变化"，Agent 可自动触发联网搜索 | 必须 |
| AG-05 | 搜索调用正确 | 工具调用日志中搜索参数（关键词）合理，搜索结果返回后 Agent 能整合回答 | 必须 |
| AG-06 | 工具调用错误处理 | 搜索 API 返回错误时，Agent 不崩溃，给出友好提示 | 必须 |
| AG-07 | 代码执行 | 发送"帮我运行一下这段代码"，Agent 可安全执行并返回结果 | 建议 |
| AG-08 | 代码执行安全 | 恶意代码（如死循环 `while(true){}`）不会导致后端进程卡死 | 建议 |
| AG-09 | 工具调用调试模式 | 后端可通过配置开关开启调试日志模式，输出完整 tool call 链路（LLM决策→工具选择→参数→返回→反思） | 建议 |

### 3.3 任务规划

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| AG-09 | 复杂任务拆解 | 发送"帮我准备 Vue 面试"，Agent 拆解为至少 2 个以上步骤执行 | 必须 |
| AG-10 | 分步执行展示 | 每一步的执行状态（进行中/已完成）在前端可视化展示 | 必须 |
| AG-11 | 反思迭代 | 工具返回结果后 Agent 能基于结果继续推理，不直接终止 | 必须 |

### 3.4 记忆系统

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| AG-12 | 短期记忆 | 同一会话中 Agent 至少能维持最近 10 轮对话的上下文 | 必须 |
| AG-13 | 长期记忆 | 关闭页面重新打开后，历史对话完整恢复 | 必须 |
| AG-14 | 薄弱点记忆 | 刷题模式中答错的题目/知识点，在后续会话中 Agent 能识别并提及 | 建议 |

## 4. 三种辅导模式验收

### 4.1 刷题模式

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| QZ-01 | 自动出题 | 进入刷题模式后 Agent 自动按知识点出题，包含题干和选项/开放性答案 | 必须 |
| QZ-02 | 难度控制 | 可指定难度（基础/中级/进阶），Agent 按需出题 | 建议 |
| QZ-03 | 批改评分 | 用户提交答案后 Agent 给出评分（如 8/10）和有改进建议 | 必须 |
| QZ-04 | 答案解析 | 批改后附带正确答案和详细解析 | 必须 |

### 4.2 问答模式

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| QA-01 | 自由提问 | 任意前端八股问题可获得专业回答 | 必须 |
| QA-02 | 代码示例 | 涉及代码的问题回答中附带可运行的代码示例 | 建议 |
| QA-03 | 追问连续 | 在回答基础上继续追问，Agent 能正确理解追问指代的内容 | 必须 |
| QA-04 | 知识溯源 | Agent 回答能标注信息来源（"根据 MDN 文档…" / "根据搜索结果显示…"） | 建议 |
| QA-05 | 用户反馈标记 | 每条 Agent 回复下方有"有帮助/需改进/不正确"反馈按钮，点击后可提交 | 建议 |

### 4.3 模拟面试模式

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| MI-01 | 面试开场 | Agent 以面试官身份开场，自我介绍并说明面试流程 | 必须 |
| MI-02 | 面试提问 | 按节奏依次提问，覆盖多个知识点领域 | 必须 |
| MI-03 | 追问能力 | 用户回答后面试官能进行 1-2 轮深入追问 | 必须 |
| MI-04 | 面试结束 | 面试流程自然结束（如"面试到此结束"），不无限循环 | 必须 |
| MI-05 | 总结报告 | 面试结束后生成结构化报告：**得分、薄弱点、改进建议、学习计划** | 必须 |
| MI-06 | 报告可保存 | 总结报告可导出或保存到历史记录中 | 建议 |

## 5. 非功能验收

### 5.1 性能

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| PF-01 | 首屏加载时间 | 前端页面从输入 URL 到可交互 ≤ 3s | 建议 |
| PF-02 | 消息响应时间 | 纯问答场景：消息发送到输出首个文字 ≤ 3s | 必须 |
| PF-03 | 工具调用响应 | 含工具调用场景：消息发送到完整回复 ≤ 10s | 建议 |
| PF-04 | 历史会话加载 | 打开 20+ 会话列表时，列表渲染 ≤ 2s | 建议 |

### 5.2 错误处理

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| ER-01 | API 不可用 | DeepSeek API 不可用时，前端展示"服务暂不可用"提示，不崩溃 | 必须 |
| ER-02 | 网络错误 | 网络断开后发送消息，展示网络错误提示，恢复后可正常使用 | 必须 |
| ER-03 | 超长输入 | 输入超长文本（>2000 字），不导致页面卡死或崩溃 | 必须 |
| ER-04 | 工具超时 | 工具调用超过设定时间，自动终止并提示用户 | 建议 |
| ER-05 | 异常输入 | 输入特殊字符/空内容/纯空格，输入框应有校验拦截 | 必须 |

### 5.3 边界场景

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| BC-01 | 话题限制 | 用户询问非前端话题（如"帮我写个 Python 脚本"），Agent 礼貌拒绝并引导回前端话题 | 建议 |
| BC-02 | 超长对话 | 超过 50 轮的会话，Agent 仍然能保持上下文连贯 | 建议 |
| BC-03 | 并发消息 | 快速连续发送多条消息，不会导致消息顺序错乱或丢失 | 必须 |
| BC-04 | 回答质量声明 | Agent 对存在争议的八股问题主动声明"业界存在不同观点"，不输出绝对化结论 | 建议 |

## 6. 代码与工程验收

### 6.1 代码质量

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| CQ-01 | TypeScript 覆盖 | 前后端核心逻辑 100% TypeScript，不使用 `any`（合理场景除外） | 必须 |
| CQ-02 | 组件粒度 | 前端组件单一职责，不复用组件超过 200 行需拆分 | 建议 |
| CQ-03 | API 封装 | 后端 API 路由统一前缀，错误响应格式统一 | 必须 |
| CQ-04 | 日志规范 | 后端关键操作（API 调用、工具调用、报错）有日志输出 | 建议 |

### 6.2 Git 规范

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| GC-01 | Commit 规范 | 使用 Conventional Commits 规范（feat/fix/refactor/docs 等） | 必须 |
| GC-02 | 仓库完整 | `.gitignore` 正确配置（不提交 node_modules、.env、dist） | 必须 |
| GC-03 | README | 包含项目简介、技术栈、快速启动、目录结构、架构图五要素 | 必须 |

### 6.3 安全

| 编号 | 验收项 | 验收标准 | 类型 |
|------|--------|----------|------|
| SC-01 | API Key 安全 | DeepSeek API Key 仅在后端使用，不出现在前端代码或请求中 | 必须 |
| SC-02 | .env 保护 | .env 文件在 .gitignore 中，不提交到仓库 | 必须 |
| SC-03 | 代码执行隔离 | 代码执行工具在独立沙箱/子进程中运行，有超时终止机制 | 建议 |
