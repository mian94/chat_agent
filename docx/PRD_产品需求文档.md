> 版本：v1.0  
> 最后更新：2025-07-13

---

## 1. 项目概述

### 1.1 项目名称

**前端八股面试智能辅导 Agent**（Frontend Interview Tutoring Agent）

### 1.2 项目背景

前端开发者面试中，"八股文"（基础知识问答）是绕不开的环节。目前市面上的刷题工具（如力扣、牛客网）以题库为主，缺乏个性化辅导和深度交互能力。大语言模型的兴起使得打造一个**具备自主规划、记忆、工具调用能力的智能辅导 Agent** 成为可能。

### 1.3 项目目标

构建一个基于 LLM 的智能辅导 Agent，为前端开发者提供**刷题练习、知识问答、模拟面试**三位一体的面试备考体验。项目同时作为高质量个人作品集，展示 Agent 架构设计、全栈开发能力和前端交互设计。

## 2. 产品定位

| 维度 | 内容 |
|------|------|
| **产品形态** | Web 应用（本地运行，不涉及公网部署） |
| **核心价值** | 个性化前端面试辅导，模拟真实面试场景 |
| **差异化** | 非固定题库，Agent 可自主出题、批改、总结薄弱点，支持联网获取最新面试题 |
| **使用场景** | 个人日常刷题、面试前集中模拟、知识点查漏补缺 |

## 4. 功能需求

### 4.1 三种面试辅导模式

#### 模式一：刷题模式（Quiz Mode）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 自动出题 | Agent 根据当前用户薄弱点或指定知识点，自动生成面试题目 | P0 |
| 作答交互 | 用户输入答案后，Agent 进行批改并给出评分和改进建议 | P0 |
| 难度分级 | 题目按难度（基础/中级/进阶）递进 | P1 |
| 错题回顾 | 自动记录答错的题目，后续优先复现 | P1 |
| 每日推荐 | 根据历史表现推荐每日刷题计划 | P2 |

#### 模式二：问答模式（Q&A Mode）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 自由提问 | 用户可以任意提问前端八股相关问题 | P0 |
| 知识来源追溯 | Agent 回答时标注参考来源（文档/网页链接） | P1 |
| 追问能力 | 支持多轮上下文连续的追问 | P0 |
| 代码示例 | 回答中可附带可运行的代码示例 | P1 |

#### 模式三：模拟面试模式（Mock Interview Mode）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 面试启动 | Agent 扮演面试官，按流程开始面试 | P0 |
| 多轮追问 | 根据用户回答，面试官进行追问和深入考察 | P0 |
| 面试计时 | 可选计时模式，模拟真实面试节奏 | P2 |
| 面试总结 | 面试结束后生成综合评价报告，包括薄弱点分析 | P0 |
| 个性化建议 | 根据面试表现生成针对性学习计划 | P1 |

### 4.2 Agent 核心能力

#### 4.2.1 工具调用（Tool Use）

| 工具名称 | 功能说明 | 优先级 |
|----------|----------|--------|
| **联网搜索** | 实时搜索前端面试题、新技术动态；底层调用搜索 API | P0 |
| **本地知识库检索** | 从用户上传的文档/笔记中检索相关内容 | P1 |
| **代码执行器** | 安全沙箱中运行前端代码并返回结果（如运行 JS 代码片段） | P1 |
| **题目生成器** | 根据上下文和知识点自动生成面试题 | P0 |

#### 4.2.2 记忆系统（Memory）

| 记忆类型 | 实现方式 | 说明 | 优先级 |
|----------|----------|------|--------|
| 短期记忆 | 对话上下文窗口 | 当前会话中携带历史消息，维持多轮对话连贯性 | P0 |
| 长期记忆 | IndexedDB / JSON 文件 | 持久化存储用户偏好、历史对话、薄弱点记录 | P0 |
| 薄弱点记忆 | 结构化数据存储 | 记录每次作答/面试中暴露的知识薄弱点 | P1 |

#### 4.2.3 任务规划（Planning）

| 能力 | 说明 | 优先级 |
|------|------|--------|
| 任务拆解 | 复杂需求（如"帮我准备 Vue 面试"）自动拆解为多步执行 | P0 |
| 分步执行 | 按规划的步骤逐步执行，每步输出中间结果 | P0 |
| 反思迭代 | 工具返回结果后自动判断是否需要进一步操作 | P0 |
| 失败重试 | 工具调用失败时自动重试或切换方案 | P1 |

### 4.3 前端交互界面

#### 4.3.1 聊天界面

| 模块 | 说明 | 优先级 |
|------|------|--------|
| 消息气泡 | 用户消息与 Agent 消息区分展示，支持 Markdown 渲染 | P0 |
| 代码高亮 | 代码块语法高亮 + 一键复制 | P0 |
| 输入框 | 支持文本输入、Enter 发送、Shift+Enter 换行 | P0 |
| 加载状态 | Agent 思考/调用工具时展示动态加载动画 | P0 |
| 模式切换 | 聊天界面顶部可切换三种辅导模式 | P0 |

#### 4.3.2 工具调用可视化面板

| 模块 | 说明 | 优先级 |
|------|------|--------|
| 思考过程展示 | Agent 当前的思考步骤实时展示 | P0 |
| 工具调用日志 | 具体调用的工具名称、参数、返回结果（可折叠） | P1 |
| 执行进度条 | 多步任务时展示总体进度 | P2 |

#### 4.3.3 会话管理

| 模块 | 说明 | 优先级 |
|------|------|--------|
| 会话列表 | 侧边栏展示历史会话记录 | P0 |
| 新建会话 | 一键开启新会话 | P0 |
| 删除会话 | 删除不需要的历史会话 | P0 |
| 会话重命名 | 自动根据对话内容生成会话标题 | P2 |

#### 4.3.4 配置面板

| 模块 | 说明 | 优先级 |
|------|------|--------|
| Agent 角色 | 查看当前 Agent 角色设定（系统 Prompt） | P1 |
| 模型选择 | 切换不同 LLM 模型（预留扩展） | P2 |
| 知识库管理 | 上传/查看/删除本地知识文档 | P1 |
| 其他设置 | 联网开关、模式偏好等 | P2 |

### 4.4 知识库管理

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 文档上传 | 支持上传 Markdown/PDF/TXT 格式的前端笔记 | P1 |
| 文档检索 | 上传后 Agent 可检索文档内容辅助回答 | P1 |
| 联网抓取 | Agent 自动搜索网络上的面试题和知识点 | P0 |
| 文档管理 | 查看已上传文档列表，支持删除 | P1 |

### 5.1 核心数据流

```
用户输入 → Agent 调度引擎 → 任务拆解（如需）
                          → 判断是否需要工具
                            → 是：调用工具 → 处理结果 → 反思 → 继续或输出
                            → 否：直接调用 LLM → 生成回复
                          → 更新记忆 → 返回前端展示
```

## 7. 非功能需求

### 7.1 性能要求

| 指标 | 目标值 |
|------|--------|
| 消息发送到首次响应 | ≤ 3s（基础问答）/ ≤ 8s（含工具调用） |
| 历史会话加载 | ≤ 1s |
| 工具调用超时 | 单次工具调用超时 15s，超时自动重试或降级 |

### 7.2 可维护性

| 要求 | 说明 |
|------|------|
| 代码规范 | 统一 ESLint + Prettier 配置，TypeScript 严格模式 |
| 目录结构 | 前后端分离，模块化组织，命名规范 |
| 组件化 | 前端组件粒度合理，可复用 |
| 注释规范 | 关键逻辑、工具函数、API 接口必须有注释 |
| Git 规范 | 遵循 Conventional Commits（feat/fix/refactor/docs 等） |

### 7.3 安全性

| 要求 | 说明 |
|------|------|
| API Key 保护 | DeepSeek API Key 仅存于后端，不暴露到前端 |
| 代码执行沙箱 | 代码执行工具运行在安全沙箱中，防止恶意代码影响宿主环境 |
| 无用户认证 | 本地运行，不涉及用户密码等敏感信息 |

### 7.4 可靠性

| 要求 | 说明 |
|------|------|
| 错误兜底 | LLM API 不可用时给出友好提示，不崩溃 |
| 工具调用容错 | 工具调用失败时有降级策略，不影响整体对话 |
| 上下文截断处理 | 超长对话自动截断或总结，保证关键信息不丢失 |

### 7.5 回答质量保障

| 要求 | 说明 | 实现方式 |
|------|------|----------|
| 权威答案参考集 | 为高频前端八股题（如 Vue 生命周期、React Fiber、闭包等）准备一份标准答案参考集 | 本地 Markdown/JSON 文件维护，作为后续校验基准 |
| 答案自动校验 | Agent 输出面试答案时，与参考集做对比，发现重大偏差时提示用户"该回答可能与常规理解不一致" | 后端对比逻辑 + 前端标签提示 |
| 来源优先级制度 | Agent 回答时优先参考联网搜索结果/已上传文档，LLM 原生知识作为兜底，降低幻觉风险 | 工具调用 Prompt 中约束来源优先级 |
| 用户反馈标记 | 用户可对 Agent 的回答标记"有帮助/需改进/不正确"，用于持续优化 | 前端反馈按钮 + 后端记录存储 |
| 回答质量声明 | Agent 在模棱两可的问题上主动声明"该问题在业界存在不同观点"，不输出绝对化结论 | 系统 Prompt 约束 |

## 8. 分阶段开发计划

### 阶段 1：基础搭建（预计 1-2 天）

- [ ] 初始化 Vue3 + Vite + TypeScript + Element Plus 前端项目
- [ ] 初始化 Express + TypeScript 后端项目
- [ ] 搭建基本目录结构
- [ ] 配置 ESLint + Prettier
- [ ] 实现前后端通信（Axios）
- [ ] 实现最简聊天界面：消息气泡、输入框、发送按钮

### 阶段 2：基础对话机器人（预计 2-3 天）

- [ ] 后端封装 DeepSeek API 调用
- [ ] 前端对接实现一问一答
- [ ] 短期上下文记忆（携带历史消息）
- [ ] 系统 Prompt 定义 Agent 身份
- [ ] Markdown 渲染 + 代码高亮
- [ ] 会话管理（新建/删除/历史列表）
- [ ] 本地存储聊天记录（IndexedDB）

### 阶段 3：Agent 核心能力（预计 4-6 天，核心阶段）

- [ ] **Function Calling 对接**：定义工具描述 JSON，让 LLM 能调用后端工具
- [ ] **联网搜索工具**：接入搜索 API，Agent 可实时搜索前端面试题
- [ ] **工具执行循环**：LLM 调工具 → 后端执行 → 结果回传 → LLM 整合输出
- [ ] **任务规划**：Prompt 约束复杂任务自动拆分步骤
- [ ] **反思迭代**：工具执行后自动判断是否需要继续循环
- [ ] **工具调用可视化**：前端展示 Agent 思考步骤和工具调用日志
- [ ] **工具调用调试模式**：后端输出完整 tool call 链路日志（LLM 决策 → 工具选择 → 参数构造 → 返回结果 → 反思判断），支持开发期间开关调试模式

### 阶段 4：三种辅导模式（预计 3-4 天）

- [ ] **刷题模式**：系统 Prompt 切换 + 出题/批改/评分流程
- [ ] **问答模式**：自由提问 + 知识溯源
- [ ] **模拟面试模式**：面试官角色扮演 + 多轮追问 + 总结报告
- [ ] **模式切换 UI**：顶部模式切换入口，界面根据模式做微调
- [ ] **薄弱点记录**：自动记录答题薄弱点

### 阶段 5：知识库与增强功能（预计 3-4 天）

- [ ] **本地知识库检索**：文档上传（Markdown/TXT），Fuse.js 全文检索
- [ ] **代码执行器**：沙箱中运行 JS 代码，返回执行结果
- [ ] **知识库管理 UI**：上传/查看/删除文档
- [ ] **面试总结报告**：结构化展示薄弱点分析和学习建议
- [ ] **长对话上下文管理**：自动截断或摘要压缩

### 阶段 6：打磨与上架（预计 2-3 天）

- [ ] UI 细节打磨（过渡动画、空状态、错误状态）
- [ ] 边界情况处理（超时、异常输入、空响应）
- [ ] TypeScript 类型补全、修复 lint 错误
- [ ] 完善 README：项目介绍、快速启动、架构图
- [ ] 录制演示视频/截图
- [ ] **高频八股答案校验**：整理 20+ 道高频前端八股题的标准答案参考集，接入自动校验流程
- [ ] GitHub 仓库清理，整理 commit history
